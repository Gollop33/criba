feat(api-ml): verificacion REAL contra la API + deteccion de ofertas muertas

El usuario configuro la app y los permisos a medias. Analizando que devuelve la
API se descubrio el estado real y se aprovecho todo lo que SI funciona.

ESTADO MEDIDO DEL TOKEN:
  OK   /users/me                 200
  OK   /categories/{id}          200
  OK   /products/{id}            200  <-- el permiso de catalogo YA funciona
  403  /items/{id}                     <-- falta el permiso de publicaciones
  403  /sites/MLB/search

  /products/ devuelve nombre, marca, atributos, imagenes y status ("active"),
  pero buy_box_winner viene null: AHÍ vive el precio. Sin el permiso de items
  no hay precio. Con catalogo sí hay: existencia, estado activo y nombre real.

BUG PROPIO ENCONTRADO Y CORREGIDO: el verificador buscaba el id directamente en
la URL del post, pero 186 de las 191 URLs de ML de la fila son enlaces cortos
meli.la. Resultado: solo 5 de 191 eran verificables (2,6%). Ahora se RESUELVE el
enlace corto con cache_melila antes de extraer el id.

MEDICION DESPUES DEL ARREGLO (45 productos probados):
   45  activo y correcto
   13  sin id reconocible
    6  403 (permiso de items)
    2  404 PRODUCTO NO EXISTE
De 2,6% a 85% de verificabilidad sobre lo que se puede probar.

El 404 es oro: significa que el producto YA NO EXISTE en el catalogo de ML. Los
dos detectados (Monitor LG UltraGear y Teclado Redragon Kumara) estaban en la
fila listos para publicarse y habrian mandado al grupo a una pagina muerta. Es
exactamente el "todo esta atrasado" que reporto el usuario.

verificar_producto.py:
  - consultar() distingue respuesta de catalogo y de publicacion.
  - verificar_post() resuelve el enlace corto, compara el NOMBRE real con el del
    post (ratio >= 50%) -> pilla enlaces cruzados, y detecta estado != active.
  - Informa de sin_precio_api cuando el catalogo no da precio, sin inventarlo.

publicar_proximo.py: nueva PUERTA 0.5 antes de resolver el enlace. Descarta la
oferta si el producto no existe (404), si el nombre no coincide o si esta
inactivo. Si la API no responde (sin token, 403, timeout) NO descarta nada: la
verificacion es un extra, nunca un requisito.

Verificado en el publicador real:

       Se descarta: el enlace llevaria a una pagina muerta.
    ⛔ [API ML] el producto YA NO EXISTE (404): Teclado Redragon Kumara
    ✅ [API ML] producto verificado (activo + nombre OK)
    -> Post seleccionado: Notebook Lenovo IdeaPad Slim 3

diagnosticar_api_ml.py: ahora distingue lo que funciona de lo que falta. Deja
claro que el catalogo YA va y que solo falta el permiso de items para el precio,
y avisa de que un error rojo en el formulario impide guardar los permisos (que
es lo que le estaba pasando).

No se rompio nada: 20/20 pruebas del validador, 0 rechazos en la auditoria de la
fila y la generacion de la fila sigue igual.
